# StashDB 来源

StashDB 是作品、出演者与厂牌的外部资料来源。配置入口是「Peach 配置 → 来源与订阅 → StashDB」。它使用 StashDB 只读 GraphQL 接口，与本机 Stash 数据库适配器分开。

## 连接与选项

按照 [StashDB 接入说明](https://guidelines.stashdb.org/docs/faq_getting-started/stashdb/accessing-stashdb/) 注册并取得自己的 API key，在密码框中保存，再点连接检查。服务端只返回凭据是否存在，密码框留空会保留已保存的 key，移除凭据有单独按钮。

来源默认关闭。启用后，资料扫描按图片选项选择采集范围。开启作品图片时查询作品匹配；关闭作品图片时只匹配所选媒体已关联的演员与厂牌，每个身份只查询一次，不搜索作品。演员照片仍由独立选项控制，作品演员纠正仅在作品图片开启时生效。图片选项默认开启，演员纠正与自动采用默认关闭。

「媒体库与导入」里的文件名匹配在本地读取文件名中的演员与厂牌名称并建立归属，不请求 StashDB。「来源与订阅」里的演员纠正使用已经匹配的 StashDB 作品名单校正文件名归属，保留手工指定的演员。关闭作品图片时，演员与厂牌采集只补已有关联的身份和可用照片，不改作品名单；人工复核仍可明确查询作品。

「数据管理 → 扫描与采集」与全站扫描浮层提供「停止扫描」。停止后保留已完成的登记、图片和资料，在下一个安全停点退出；在途网络请求结束或超时后退出，不再发起下一请求。暂停状态也能停止，停止任务不自动续跑；需要采集时发起新任务。只想暂时等候时使用暂停与继续。

在本机库内搜索作品或演员，选择条目后预览 StashDB 结果。作品结果列出标题、发行日期、厂牌、出演者与匹配理由；演员结果列出同名区分信息。先查看来源条目，再确认采用。扫描保留的结果可以从「复核资料扫描找到的结果」入口选择。库内值变化后，作品复核令牌失效，需要重新预览。

保存设置后，可在同一分区启动资料扫描，也可在「数据管理 → 扫描与采集」选择补全资料。手工查找与排队复核统一位于「人工复核 → StashDB」，来源分区提供直达链接。选择匹配后确认采用，或忽略当前作品的这一组匹配；忽略会保留本机资料，并在本机线索与选项未变化时跳过自动复核。完成回执单列 StashDB 已采用、待复核与已完成跳过的数量；番号识别为零不代表 StashDB 没有结果。连接检查成功时显示独立确认文字，即使账号没有显示名也会确认连接。

图片安装在 `generated/avatars` 与 `generated/covers`，与浏览器媒体接口使用同一目录。启动扫描或人工采用时，只复制本来源缓存中尚未安装的图片组，保留缓存原件和正式目录已有的图片。图片下载失败会保留当前图片并提示重试。演员纠正按已关联姓名或别名保留规范身份，头像跟随同一身份。

已完成作品按本机线索、采集选项和已安装图片判定；无变化时不重复查询。已保存的演员图片按 StashDB 身份跳过，多个作品共用一位演员时不重复下载。改变本机线索、启用新的采集选项或移除已装图片后，可再次扫描。

待复核匹配计入数据管理顶部的人工复核读数，也显示在复核页的 StashDB 分类中。无变化的待复核候选保留在队列，不重复远端查询；无结果的成功查询缓存一天。改变本机线索、忽略规则或匹配门槛后重新查询，网络失败和图片安装失败可重试。人工预览可随时重新查询。

「匹配时忽略文件名文本」每行填写一个字母、字符、词或短语，按不区分大小写的字面文本清理文件名线索。可单独填写 `!`；不支持正则表达式，文件原名和已存资料不变。自动采用最低置信度可设为 50–100%，默认 85%；仅影响自动采用，人工复核仍可选择候选。

「跳过失败或无结果的 StashDB 搜索」默认关闭。开启后，本机线索与匹配选项未变化的失败结果不再自动重试，无结果查询也不受一天缓存期限限制；改变线索或关闭选项后可重试。限流仍按来源冷却，不记作单件永久失败。人工预览始终可重新查询。

「仅匹配新增媒体」默认关闭。开启时记录当前库的登记边界，只处理此后登记的视频；关闭后包含较早的视频。重新开启会建立新的边界。该选项只控制 StashDB 扫描，文件登记、其他资料来源与人工预览保持各自用途。

## 作品匹配

线索来自当前标题、发行日期、厂牌、规范演员与别名，以及文件名中的日期、厂牌与演员字段。整段文件名不是唯一搜索词。查询依次组合厂牌与日期、出演者与日期、厂牌与出演者，以及清理后的标题。厂牌连写、空格、标点与父厂牌名称参与归一化。

排序合计标题相似度、确切发行日期、厂牌、演员名或别名、时长。自动采用要求多条线索一致、得分达到保存的门槛、领先下一条至少 0.12，且查询结果没有被截断。只凭标题、日期或厂牌的一条线索，以及日期或厂牌冲突，都交给复核。并列结果不自动任选一条。

每次查询最多读取 25 条演员、25 条厂牌和 50 条作品；截断时停止自动采用，提示补全本机线索。一次匹配最多组合四种作品查询。同一批次复用有界内存查询缓存，重复作品不会重复查询相同条件。

## 写入与图片

StashDB 身份使用规范 UUID，演员与厂牌登记 `entity_external_ref`。同名且有不同来源身份的人物保持区分；标为模糊身份的演员不自动加入。演员纠正替换本来源及文件名来源的关系，保留逐件手动和其他来源的归属；规范关系与演员标签同步。人工确认的 StashDB 结果使用 `review:stashdb`，自动结果使用 `auto:stashdb`。已受用户或其他复核保护的作品字段保持其取值。

演员照片与作品图片单独采集。自动采用只补缺图；人工采用可以按已保存的图片选项换图。照片按竖图优先、面积从大到小挑选，验证文件内容与尺寸后写入现有头像安装链；作品图片复用现有封面安装链与来源证据。演员照片至少长边 500、短边 300 像素；不安装动画图片。图片请求不带 API key，不跟随重定向，仅访问解析为公网地址的 HTTPS 来源。

API key 保存在本机 secrets 目录，不放进 localStorage、URL、来源快照或诊断返回。固定接口为 `https://stashdb.org/graphql`，不接受自定义 GraphQL 地址。每个网络请求有 20 秒超时，API 响应最多 4 MiB，图片最多 12 MiB。API 与图片请求共享一秒间隔；遇到 429 保存服务端 `Retry-After`，冷却期间不继续请求。

## 来源约定

2026-10-23 核对以下官方说明与协议：

- [使用 StashDB](https://guidelines.stashdb.org/docs/faq_getting-started/stashdb/using-stashdb/)：复核优先、按字段选择采用内容。
- [模糊演员](https://guidelines.stashdb.org/docs/scenes/edit/scene-performers/ambiguous-performers/)：不把模糊身份当成确定演员。
- [发行日期](https://guidelines.stashdb.org/docs/scenes/edit/scene-date/preferred-scene-dates/)：读取发行日期字段，不用拍摄日期代替；近似日期与冲突交给复核。该页将此约定标为尚待正式批准。
- [演员图片顺序](https://guidelines.stashdb.org/docs/faq_getting-started/performers/image-sort-order/)：大尺寸竖图在前，横图在后。
- [Stash-Box 协议](https://github.com/stashapp/stash-box/tree/master/graphql/schema)：使用变量化只读查询，不提交修改、投票、指纹或上传图片。

隔离验证使用临时账本、合成图片和假 GraphQL 响应。没有预置 StashDB 账号或凭据，也没有对真实馆藏执行采集。
